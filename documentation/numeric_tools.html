Numerical tools

The numerical tools are a set of tools that can be used to solve a variety of problems.

MPMDofLocations class

The locations of the entities of a material point or RKPM model: the global indices of the local degrees of freedom of its finite elements and constraints (DofLocations, the LM array), and of its background cells, cell elements and particles. They are built on the numbering of the degrees of freedom of the active domain (DofNumbering, the ID array). Neither is ever changed: moved particles, or changed constraints, make new locations on the same numbering (withNewLocationsOf()).

class edelweissmeshfree.numerics.doflocations.MPMDofLocations(numbering, elements=None, constraints=None, cells=None, cellElements=None, particles=None)[source]

The locations of the entities of a material point or RKPM model in the numbering of the degrees of freedom of its active domain: those of DofLocations – the finite elements and the constraints – and those of the background cells, the cell elements and the particles, which are computed like elements.

The locations of the particles are the locations of the nodes their kernel functions reach, node after node, on each node the same fields. Moving particles reach other nodes of the same numbering: new locations of the particles on the same numbering, see withNewLocationsOf().

_accumulateNodalFluxesFieldwise(entities)

Count the nodal fluxes Σ_entities Σ_nodes ( nDof (field) ) for each field.

A node shared by many entities contributes the same count to each of them, so the nodes are first counted, and each distinct node’s fields are then looked up only once, weighted by that count. The result is an integer sum and hence identical to visiting every node of every entity.

_locateNodeCouplingEntities(entities)

Creates a dictionary containing the location (indices) of each entity (elements, …) within the DofVector structure.

The location of an entity is the indices of the field variables of its nodes, node after node and, on each node, field after field as the entity lists them (fields), reordered by its dofIndicesPermutation unless that is None.

An entity that cannot be located raises: one of its nodes does not have a field the entity couples there, or the field variable is not part of the numbering (see _noLocationError()); so does an entity that lacks nodes, fields or dofIndicesPermutation, or lists fewer fields than it has nodes – whether there are few entities or many.

The entities are independent of each other, so they are located in chunks on the thread pool (mapChunksInParallel()), unless there are so few of them that handing them to the pool would cost more than it saves: then the calling thread locates them. The dictionary holds the entities in the order they were given.

Parameters:

entities (list) – The list of entities to locate.

Returns:

A dictionary containing the location mapping.

Return type:

dict

Raises:

ValueError – If an entity cannot be located.

_mergeEntities()

Merge what is known per kind of entity: the lists of the elements and of the constraints the locations hold, the merged mapping of every entity to its indices, and the accumulated nodal fluxes. The locations are immutable: the merged mapping is made anew for every locations, never changed in place, so that whoever still holds the old locations holds a mapping that stays valid.

checkEveryDofIsLocated(indicesRelatedByMultiPointConstraints=None)

Refuse a degree of freedom that no located entity touches. Such a degree of freedom has a number, but no row in the system matrix: a node that only an entity without kernels touches (e.g. a contact facet) is such a node. A solver cannot pin it with a Dirichlet boundary condition, nor integrate it, so the discrete system is not built.

A multi-point constraint is no entity and owns no degrees of freedom, but a degree of freedom it relates, as slave or as master (e.g. of the reference point of a rigid body), has its row through the condensation.

Parameters:

indicesRelatedByMultiPointConstraints (ndarray | None) – The indices of the degrees of freedom that multi-point constraints relate; None for none.

Raises:

ValueError – If a degree of freedom of the numbering is in no location; the error names the node and the field.

withNewLocationsOf(constraints, movedEntities=None)

The locations of the same entities in the same numbering, with the constraints, and the further entities that moved, located anew after their connectivity changed.

A contact search re-assigns which nodes a constraint couples. That changes the constraints’ locations and nothing else: no node, field, scalar variable or element is touched, so the numbering and the locations of every element stay valid, and only what is derived from the constraints is computed again – by the same methods, in the same order, as the constructor computed it. That is a small fraction of what making locations for the same model costs.

A change that moves the numbering – a mesh refinement, a constraint gaining a scalar variable of its own – is not a change of the connectivity, and needs a new DofNumbering: this method refuses it.

Parameters:

  • constraints (list) – The constraints, with their current connectivity.

  • movedEntities (list) – The further entities whose connectivity changed (see the constructor); the others keep the locations they were given. Only meaningful where the numbering stands, as for the constraints.

Returns:

The new locations; these locations are not changed.

Return type:

DofLocations

Raises:

ValueError – If the scalar variables of the constraints are not exactly those the numbering numbers, in this order, or a moved entity is not located in these locations.

property nAccumulatedNodalFluxesFieldwise: dict

For the Abaqus like convergence test, the number of degrees of freedom ‘entity-wise’ per field, that is Σ_(elements+constraints) Σ_nodes ( nDof (field) ). Computed from the entities of these locations at the first request, and kept: only the convergence criteria ask, so a solver without them does not pay. The count of the elements, and of the further entities that did not move, is shared with the locations these were made from: only the constraints, and the entities that moved, are counted again.

Returns:

The number of accumulated fluxes, for every field of the numbering.

Return type:

dict
