Numerical tools

The numerical tools are a set of tools that can be used to solve a variety of problems.

MPMDofLocations class

The locations of the entities of a material point or RKPM model: the global indices of the local degrees of freedom of its finite elements and constraints (DofLocations, the LM array), and of its background cells, cell elements and particles, all located by the one protocol of an entity (BaseNodeCouplingEntity: nodes, fields per node, permutation, scalar variables). The inertia of the finite elements is assembled at the nodes (elementsWithNodalInertia); the particles’ lumped mass is assembled by the discrete system (assembleLumpedMassOfEntitiesWithOwnInertia()). They are built on the numbering of the degrees of freedom of the active domain (DofNumbering, the ID array). Neither is ever changed: moved particles, or changed constraints, make new locations on the same numbering (withNewLocationsOf()).

class edelweissmeshfree.numerics.doflocations.MPMDofLocations(numbering, finiteElements=None, constraints=None, cells=None, cellElements=None, particles=None)[source]

The locations of the entities of a material point or RKPM model in the numbering of the degrees of freedom of its active domain: those of DofLocations – the finite elements and the constraints – and those of the background cells, the cell elements and the particles, which are computed like elements: they follow the finite elements in elements, and they are located by the same protocol of an entity as the elements are.

The locations of the particles are the locations of the nodes their kernel functions reach, node after node, on each node the same fields. Moving particles reach other nodes of the same numbering: new locations of the particles on the same numbering, see withNewLocationsOf().

Parameters:

  • numbering (DofNumbering) – The numbering of the degrees of freedom of the active domain.

  • finiteElements (list) – The finite elements that take part in the discrete system.

  • constraints (list) – A list of constraints.

  • cells (list) – A list of cells.

  • cellElements (list) – A list of cell elements.

  • particles (list) – The list of particles (RKPM).

Attributes:

_accumulateNodalFluxesFieldwise(entities)

Count the nodal fluxes Σ_entities Σ_nodes ( nDof (field) ) for each field.

A node shared by many entities contributes the same count to each of them, so the nodes are first counted, and each distinct node’s fields are then looked up only once, weighted by that count. The result is an integer sum and hence identical to visiting every node of every entity.

Parameters:

entities (list) – The list of entities (elements or constraints), whose nodes are considered.

Returns:

The number of accumulated fluxes per field, for every field in phenomena.

Return type:

dict

_locate(entities)

Creates a dictionary containing the location (indices) of each entity (elements, constraints, …) within the DofVector structure.

The location of an entity is the indices of the field variables of its nodes, node after node and, on each node, field after field as the entity lists them (fields), reordered by its dofIndicesPermutation unless that is None; the indices of its scalar variables (scalarVariables) follow, after the permutation.

An entity that cannot be located raises: one of its nodes does not have a field the entity couples there, or the field variable is not part of the numbering, or a scalar variable is not (see _noLocationError()); so does an entity that lacks nodes, fields, dofIndicesPermutation or scalarVariables, or lists fewer fields than it has nodes – whether there are few entities or many.

The entities are independent of each other, so they are located in chunks on the thread pool (mapChunksInParallel()), unless there are so few of them that handing them to the pool would cost more than it saves: then the calling thread locates them. The dictionary holds the entities in the order they were given.

Parameters:

entities (list) – The list of entities to locate.

Returns:

A dictionary containing the location mapping.

Return type:

dict

Raises:

ValueError – If an entity cannot be located.

checkEveryDofIsLocated(indicesRelatedByMultiPointConstraints=None)

Refuse a degree of freedom that no located entity touches. Such a degree of freedom has a number, but no row in the system matrix: a node that only an entity without kernels touches (e.g. a contact facet) is such a node. A solver cannot pin it with a Dirichlet boundary condition, nor integrate it, so the discrete system is not built.

A multi-point constraint is no entity and owns no degrees of freedom, but a degree of freedom it relates, as slave or as master (e.g. of the reference point of a rigid body), has its row through the condensation.

Parameters:

indicesRelatedByMultiPointConstraints (ndarray | None) – The indices of the degrees of freedom that multi-point constraints relate; None for none.

Raises:

ValueError – If a degree of freedom of the numbering is in no location; the error names the node and the field.

withNewLocationsOf(constraints, movedEntities=None)

The locations of the same entities in the same numbering, with the constraints, and the elements that moved, located anew after their connectivity changed.

A contact search re-assigns which nodes a constraint couples. That changes the constraints’ locations and nothing else: no node, field, scalar variable or element is touched, so the numbering and the locations of every element stay valid, and only what is derived from the constraints is computed again – by the same method, in the same order, as the constructor computed it. That is a small fraction of what making locations for the same model costs.

A change that moves the numbering – a mesh refinement, a constraint gaining a scalar variable of its own – is not a change of the connectivity, and needs a new DofNumbering: this method refuses it.

Parameters:

  • constraints (list) – The constraints, with their current connectivity.

  • movedEntities (list) – The elements whose connectivity changed: those that declare that it changes with the motion (connectivityChangesWithMotion, e.g. the particles of a meshfree model whose kernel functions reach other nodes). The others keep the locations they were given. Only meaningful where the numbering stands, as for the constraints.

Returns:

The new locations; these locations are not changed.

Return type:

DofLocations

Raises:

ValueError – If the scalar variables of the constraints are not exactly those the numbering numbers, in this order, or a moved entity is not an element located in these locations, or does not declare that its connectivity changes with the motion.

_elementsWithFixedConnectivity

The elements whose nodes stay as they are, and those whose nodes change with the motion (connectivityChangesWithMotion), which are the only ones that can be moved, see withNewLocationsOf().

_fluxesOfFixedElements

The accumulated nodal fluxes of the elements with fixed connectivity, counted when first asked for (see nAccumulatedNodalFluxesFieldwise) and shared by all locations of the numbering, see withNewLocationsOf().

_nAccumulatedNodalFluxesFieldwise

The accumulated nodal fluxes of all entities, computed at the first request.

cellElements

The cell elements that have a location.

cells

The cells that have a location, the active cells.

constraints

The constraints that take part in the discrete system, with their scalar variables. The solver evaluates exactly these, so that every constraint it evaluates has its rows in the system matrix, and every row of a constraint is filled.

elements

Everything the solver computes like an element, in the order in which it computes it. Every one of them has a location.

finiteElements

The finite elements among elements, which also holds the cells, the cell elements and the particles, in this order, after them.

property nAccumulatedNodalFluxesFieldwise: dict

For the Abaqus like convergence test, the number of degrees of freedom ‘entity-wise’ per field, that is Σ_(elements+constraints) Σ_nodes ( nDof (field) ). Computed from the entities of these locations at the first request, and kept: only the convergence criteria ask, so a solver without them does not pay. The count of the elements whose connectivity is fixed is shared by all locations of a numbering, and made once: only the constraints and the elements whose connectivity changes with the motion (connectivityChangesWithMotion) are counted again for new locations.

Returns:

The number of accumulated fluxes, for every field of the numbering.

Return type:

dict

numbering

The numbering of the degrees of freedom the entities are located in.

ofEntity

Dictionary mapping every entity (elements, then constraints) to its indices in the DofVector. It is the one mapping the consumers that handle all entities at once (the system matrix assembly, the layout of the scatter vectors) read; a single location is read by locations[entity]. The locations are immutable, so whoever still holds the old locations holds a mapping that stays valid.

particles

The particles that have a location.
